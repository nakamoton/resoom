# resoom

吹奏楽団のための、公共施設の予約支援システムです。自治体をまたいで「器楽演奏（打楽器を含む）ができる部屋」の空きを探し、予約までの作業を楽にすることを目指しています。

全体の設計は [docs/design.md](docs/design.md) にあります。

## いまできること

| 機能 | 状態 |
|---|---|
| 空き状況の検索ページ（ログインなしで使える） | 画面あり（`/search`）。`pnpm crawl` で集めたデータを検索します |
| 施設台帳（部屋ごとの楽器の可否と根拠、定員） | 画面あり。人数で絞り込めます。楽団員だけが見られます |
| ログイン（Google アカウント、招待制）と楽団員の名簿 | 画面あり。ロールは団員・施設編集・管理者 |
| 公開（Google Cloud ＋ Neon） | 手順書あり（[docs/deploy.md](docs/deploy.md)） |
| 空き照会: 大田区・渋谷区・世田谷区・品川区 | コマンドで実行できます（既定で有効） |
| 空き照会: 川崎市 | 実装済み。既定では無効（[調査メモ](docs/kawasaki-investigation.md)を参照） |
| 空き照会: 江戸川区・目黒区 | robots.txt が禁止しているため実装していません |
| 締切の管理、予約台帳、通知 | 未着手 |

公開の手順は [docs/deploy.md](docs/deploy.md) にあります。

## 動かし方

Node.js 22 以上と pnpm が必要です。

```bash
pnpm install
```

```bash
pnpm db:seed
```

```bash
pnpm crawl --days 45
```

```bash
RESOOM_DEV_LOGIN=1 ADMIN_EMAILS=admin@example.com pnpm dev
```

ブラウザで http://localhost:3000 を開くと、空き状況の検索ページが表示されます（ログイン不要）。

施設台帳はログインが必要です。ローカルでは、上の指定で「ローカル開発用のログイン」が使えます。`/sign-in` で `admin@example.com` と任意のパスワード（初回に作られます）を入れるとログインできます。この開発用のログインは、本番（`DATABASE_URL` がある環境）では指定にかかわらず使えません。

- `pnpm crawl` は、台帳の部屋の空き状況を自治体サイトから集めてデータベースに保存します（既定は今日から92日分）。本番では1日に数回、定期実行します。検索ページは保存したデータだけを読み、自治体サイトには問い合わせません。

画面は英語を主に、日本語を併記しています（日本語が苦手なメンバーのため）。施設名・部屋名には英語名（楽団での訳）を付けており、部屋のページの「Edit basic information / 基本情報を直す」から直せます。

- `pnpm db:seed` は初期データ（`data/seed/rooms.json`）を取り込みます。何度実行しても記録は重複せず、画面から追加した記録も消えません。
- データは `.data/pglite` に保存されます。消すと初期状態に戻ります。

## 施設台帳の考え方

部屋の「可・条件付き・不可」は直接書き換えず、**記録を追加する**ことで変わります。記録は次の3種類です。

- 利用したときのこと（例: ドラムセットを使ったら不可と案内された）
- 施設への問い合わせ
- 公式の資料

楽器ごとの現在の状態は、記録から次の順で決まります。

1. その楽器を名指しした記録があれば、その中で最も新しいもの
2. なければ、楽器を限定しない記録の中で最も新しいもの
3. どちらもなければ「未確認」

「ドラムセットは不可」と言われた部屋が、後日ドラムなしで問題なく使えた記録によって「可」に戻ってしまわないよう、名指しの記録を優先しています。

## 空きを調べる

```bash
pnpm availability --from 2027-01-01 --to 2027-01-31 --days sat --people 45
```

台帳で空き照会の設定がある部屋を、自治体をまたいで調べます。ログイン不要の照会だけを使い、自治体サイトごとに間隔を空けて1件ずつ問い合わせます。

- `--days`: 曜日で絞ります。絞った日しか問い合わせないので、自治体サイトへの負荷も減ります。
- `--people`: 人数です。定員がこの人数に満たない部屋は照会しません。定員が未登録の部屋は照会します。
- `--municipality`: 自治体で絞ります（例: `大田区,渋谷区`）。
- `--adapters`: 使う自治体サイトを選びます。川崎市（`kawasaki`）は、指定したときだけ使います。

自治体ごとの調査結果は `docs/*-investigation.md` にあります。

## 定員について

部屋の定員は、公式の予約システムや施設の案内から取った値と、その出典を記録しています。部屋のページの「基本情報を直す」から修正できます。`pnpm db:seed` を実行し直しても、画面で直した値は上書きされません。

公式の定員は、楽器や譜面台を置いたときに実際に入れる人数とは限りません。

## データベース

- 開発とテストでは、組み込みの PostgreSQL（PGlite）を使います。データは `.data/pglite` に保存されます。
- 本番では `DATABASE_URL`（Neon）に接続します。マイグレーションは `pnpm db:migrate` で当てます。

## 構成

```
apps/web            画面（Next.js）。ログインは Better Auth
deploy              Google Cloud への公開スクリプト（Cloud Shell で実行）と自動公開の設定
.github/workflows   main に入った変更のテストと自動公開
packages/core       楽器の可否の判定、入力の検証
packages/db         データベースの定義と読み書き
packages/adapters   自治体ごとの空き照会（いまは大田区）
scripts             コマンド（初期データの取り込み、空き検索）
data/seed           初期データ
docs                設計書と調査メモ
```
